# 会话桥形态，不做常驻守护进程

zcode 没有公开的 headless CLI，也没有进程内扩展 API（只有 MCP 服务器、7 种 shell 钩子、命令/技能提示词），因此"QQ 消息拉起无头 zcode 会话"的常驻机器人形态无法干净实现——那等于自建 agent 运行时或依赖未文档化的深链。官方"龙虾Bot"生态里常驻机器人属于 OpenClaw 类自带网关运行时的产品，不是 zcode 的角色。我们决定做**会话桥**：QQ 私聊 ↔ 当前桌面 zcode 会话双向同步，zcode 未运行时 QQ 侧只排队。代码上传输层（QQ 连接/收发/配额）与桥接层（MCP 工具/钩子）严格分层，传输层未来可独立成常驻进程，但 v1 不承诺。

## Considered Options

- **常驻守护进程**：需要 headless agent 运行时，zcode 不提供；自建则丢失 zcode 的全部编码能力。否决。
- **深链唤起桌面会话**：`zcode://` 协议的 action 未文档化、不可控。否决。
